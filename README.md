# EVE Online本地头像替换工具

把 EVE Online 客户端**本机缓存里的角色头像 jpg** 换成你自己的图，实现"只有你自己看得到"的自定义头像。

- **全程本地**：不访问任何网络接口，不碰账号，不注入进程，不改客户端资源包。
- **原理**：EVE 把角色头像当普通磁盘 HTTP 缓存用。启动时只要本地文件在就直接显示，不会重新下载。我们把文件替换掉、再设为**只读**，客户端写不进去就会一直沿用你的图。
- **可回退**：替换前会把官方原图备份到**软件根目录的 `原游戏头像备份\`**（放在软件旁边，看得见、找得到）。点「恢复到默认」会还原原图并解除只读。

> **免责声明**：本软件涉及修改游戏本地文件。更换的头像**别人看不见**，只能自己看见。
> 替换只作用于本机缓存、不影响游戏内数据，但**不能排除被官方判定违规而封号的可能性**，请谨慎使用。
> 首次启动会弹出该声明，勾选"未来不再弹出"后不再提示。

## 一、缓存文件长什么样

| 项目 | 实际情况 |
| --- | --- |
| 文件格式 | **JPEG**（`FF D8 FF E0`，JFIF），不是 PNG |
| 文件名 | `角色ID_尺寸.jpg`，例如 `1234567890_256.jpg` |
| 默认状态 | **不是只读** —— 必须手动设只读，否则会被重新下载覆盖 |

尺寸分两处存放，**位置不一样**（这点很容易踩坑）：

| 尺寸 | 位置 |
| --- | --- |
| **32 / 64** | `...\cache\Pictures\Characters\Chat\<角色ID % 100>\` |
| **128 / 256 / 512** | `...\cache\Pictures\Characters\` |
| 1024（历史遗留，偶见） | `...\cache\Pictures\Characters\` |

Chat 子目录按**角色 ID 对 100 取余**分桶（`0` ~ `99`）。实测正式服 Chat 文件全部吻合，无一例外 —— 所以 32/64 必须写到 `Chat\<ID%100>\`，写到根目录客户端根本读不到。

实测各尺寸缓存的覆盖情况与客户端实际下载一致。

`Pictures\Characters` 里可能有近万个文件，那是你**看过头像的所有人**的缓存，不是你自己的角色，所以不能拿它来列角色。

## 二、服务器识别

缓存目录名规则是 `<任意前缀>_<服务器名>`，**看后缀就能判断是哪个服**。前缀随安装位置而变，不要硬编码：

| 目录名示例 | 后缀 | 界面显示 |
| --- | --- | --- |
| `c_tranquility`、`e_eve_online_tq_tranquility`、`c_program_files_(x86)_ccp_eve_tranquility` | `tranquility` | **EVE Online欧服：正式服** |
| `c_serenity` | `serenity` | **EVE Online国服：网易服** |
| `c_eve_sharedcache_sisi_singularity`、`e_eve_online_sisi_singularity` | `singularity` | **EVE Online欧服：测试服** |

顶栏的服务器下拉框**固定列出这三个服**：

- 本机装了的服：正常显示、可以切换，启动时自动选中最近用过的那个（有偏好记录则用它记的）。
- 本机没装的服：仍然占一行，显示成 `EVE Online国服：网易服（未检测到本地缓存）`，**置灰不可选**。这样一眼就能看出程序支持哪些服、这台机器上装了哪几个。
- 扫到未知后缀的目录（自定义安装位置等）会追加在最后，可以直接选。
- 每一服各自有独立的角色列表与备份，互不干扰。
- EVE Frontier（后缀 `nebula`）是另一款游戏，明确排除。

## 三、角色列表是怎么筛出来的

### 角色 ID

本机登录过的角色 ID，从三个本地来源取并集：

1. `settings_Default\core_char_<角色ID>.dat` ← 主来源，文件名的数字就是角色 ID
2. `cache\char_<角色ID>.unlocks.yaml`
3. `Documents\EVE\logs\{Chatlogs,Gamelogs}\*_<角色ID>.txt`

### 为什么还要按启动器过滤

`core_char_*.dat` 会**永久保留**。角色转手、卖了、删了之后文件还在，
所以按上面三个来源直接列，会列出大量记录，其中不少其实已经不属于你了。

程序会读 **EVE 启动器自己的本地数据**，只显示仍然在里面的角色：

| 来源 | 内容 |
| --- | --- |
| `%APPDATA%\EVE Online\logs\*.log` | 启动器为每个账号拉取角色详情时的记录：`characterIds: [ ... ]`，这是最准的一条 |
| `%APPDATA%\EVE Online\pulsar\cache.db` | 启动器的 HTTP 响应缓存（SQLite），其中有 `https://pulsar.evetech.net//characters/<角色ID>` |

实测：大量本机记录 → 过滤后只剩仍属于你的角色，隐藏其余残留。
被隐藏的数量只写在运行日志里（`另有若干本机残留记录已隐藏`），侧栏不再单独占一行。
读取失败时（例如换了其它启动器）不做过滤，并在日志里说明。

### 角色名

只从本地游戏日志读取，**不联网**。Chatlogs 头部有一行 `Listener: 角色名`，文件名尾部就是角色 ID。
实测角色名全部识别成功。

### 刷新角色

侧栏的「刷新角色」按钮会重新读一遍本机角色列表（扫描缓存 + 启动器数据），角色有增删或换号后点一下即可。

## 四、EVE 运行状态实时检测

程序每 2.5 秒轮询一次进程。**只有游戏客户端 `exefile.exe` 在跑**时，顶栏下方才出现提示：

> **检测到 EVE Online 客户端正在运行，请先关闭游戏再替换头像**

客户端退出后提示立刻消失。切换服务器、重新扫描等操作都不会让它误亮。

判定只跟客户端走，是因为**启动器常驻后台是常态** —— 拿启动器当"EVE 正在运行"，
提示就会一直挂着消不掉。启动器的状态仍然会读到，只是不参与提示。

| 进程名 | 说明 | 是否触发提示 |
| --- | --- | --- |
| `exefile.exe` | 游戏客户端本体（`<EVE安装目录>\tq\bin64\exefile.exe`） | **是** |
| `eve-online.exe` | 新版启动器（Steam 版由 Squirrel 升级到 `app-<版本>\` 下） | 否 |
| `evelauncher.exe` | 旧版启动器 | 否 |

## 五、使用

```bash
npm install
npm start          # 开发运行
npm run pack       # 打包 → dist/EVE Online本地头像替换工具-win32-x64/
npm run icon       # 重新生成 build/icon.ico（纯标准库，不需要 Pillow）
```

应用图标用项目根目录的 `icon.ico`：既嵌进 exe，也作为窗口图标，并显示在顶栏标题左边。改动图标后重新 `npm run pack`。

流程：

1. 首次启动会弹出免责声明（中英双语，英文版在中文版下方），勾选"未来不再弹出该声明"后确认。顶栏标题右侧的 ⚠ 按钮可随时再次查看。
2. 程序自动扫描缓存目录，顶栏下拉框里选中要操作的服；找不到时可点顶栏「手动选择」（选到 `%LOCALAPPDATA%\CCP\EVE` 下对应服务器那一层，或再往里选到 `cache` 都可以）。
3. 顶栏「Language」下拉可切换界面语言（默认中文 / English），选择后整个主界面即时切换。
4. 左侧选角色 → 点「上传图片」（也可以直接把图片拖进裁剪框）→ 鼠标左键拖动位置、滚轮或「缩放」滑块调整构图。切换到其他角色时，未替换的图片和预览会自动清空。
5. 右侧「效果预览」把裁剪出的头像自动贴合到 `img/` 目录里的游戏界面截图上（人物角色、登录界面、击毁报告、聊天框、侧边栏五张），轮播展示：点右侧按钮看下一张，点下方缩略图直接跳到那张。
6. 点「替换头像」。程序先把官方原图备份到 `原游戏头像备份\角色ID\`，再写入 5 个尺寸（32/64 → `Chat\<ID%100>\`，128/256/512 → `Characters\`），最后全部设为只读。
7. **重启 EVE 客户端**后生效。

「恢复到默认」会做两件事：**用 `原游戏头像备份\` 里的原图替换回去**（含当初不存在的尺寸一并删掉），**并解除文件只读**；备份用完即清，`Chat` 子目录如果是程序建出来且已经空了也一并删掉。

备份目录优先落在软件根目录（`<exe 所在目录>\原游戏头像备份\`）；软件目录不可写时（比如装在 `Program Files`）自动退回 `%APPDATA%\EVE Online本地头像替换工具\backups\`，日志里会写明实际用的路径。

## 六、踩过的坑（都已在代码里修掉）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| `Chatlogs` 有 8 万多个文件 | 逐文件 `statSync` 把主进程同步阻塞十几秒，界面卡死 | `logindex.js`：时间戳直接从**文件名**解析，零 stat；readdir 结果缓存 30 秒 |
| 游戏日志是 **UTF-16LE** 带 BOM | 按 UTF-8 读，`Listener:` 正则永远匹配不上，一个名字都拿不到 | 按 BOM 判断编码 |
| 同一场次几百个频道文件时间戳相同 | 私有频道的 `Listener:` 是空的，"只取最新几个"会随机取到空的那种 | 按时间倒序扫，每角色最多试 40 个，全局上限 3000 次读取 |
| `contextBridge` 暴露的 `window.api` 不可配置 | 顶层写 `const api = window.api` 直接 `Identifier 'api' has already been declared`，整个 app.js 不执行 | 整个文件包进 IIFE |
| Electron 不支持 `window.prompt` | 查找角色的输入框直接报错 | 自建通用弹窗 |
| 启动时弹出免责声明会阻塞初始化 | 调试入口挂在 `await` 之后，一直挂不上 | 调试入口在任何 `await` 之前挂载 |
| 缓存里可能有旧版本留下的尺寸（如 1024） | 只按目标尺寸备份会漏掉它，恢复时残留 | 备份/恢复按「目标尺寸 ∪ 磁盘实际存在的尺寸」处理 |
| 32/64 不在 `Characters` 根目录 | 不知道 `Chat\<ID%100>\` 这条规则的话，32/64 写了也白写，客户端读不到 | `paths.js` 按尺寸决定目录：32/64 → Chat 分桶，其余 → 根目录 |
| 程序为写 32/64 新建的 `Chat\<桶>\` | 还原后留下空目录 | 还原后目录空了就删掉（`rmdir` 只在空目录上成功，不会误删） |
| Windows 的 `copyFile` 会连只读属性一起复制 | 备份文件变只读，之后删不掉 | 备份后立刻摘掉只读位 |
| Windows 上写只读文件报 `EPERM` | 回滚时往只读目标复制会失败 | 复制前先 `chmod 0666` |
| Windows 上只读文件删不掉 | `rmdir` / `unlink` 静默失败，备份残留 | 递归删除前逐项摘只读位（`store.forceRemove`） |
| 写到一半失败 | 留下"一半新一半旧"的半成品 | 先备份 → 写入 → 任一步失败**自动还原**再抛错 |
| 免责声明的复选框文字被压成一列竖排的字 | 中文没有空格，flex 项可以在任意两字之间折行，它的 `min-content` 宽度就是"一个字"，于是被挤成一根竖条 | `.chk` 显式加 `white-space: nowrap` |
| 服务器下拉框里选中的不是当前这个服 | 手动指定的目录（`--cache-dir`、手选文件夹）不在自动扫描结果里，直接拿 `candidates` 构造下拉项会把它漏掉 | 用**合并后**的候选列表（含当前目录）构造下拉项 |
| EVE 运行提示一直挂着消不掉 | 启动器 `eve-online.exe` 常驻后台，把它也算作"EVE 正在运行" | 提示只跟客户端 `exefile.exe` 走 |

## 七、已知限制

- **只对你自己可见**。别人看到的仍是服务器上的官方头像；登录界面的角色列表头像与 3D 角色模型不受影响。
- EVE 大版本更新、清理缓存、更换客户端目录后需要重新替换一遍。
- 游戏运行时替换可能失败（文件被占用），界面会实时提示。
- 需要**重启客户端**才能看到新头像。
- 角色归属依赖启动器本地数据。换了其它启动器或数据被清理时，列表会退化为显示全部本机记录。
- `原游戏头像备份\` 是"恢复到默认"唯一的依据：**手动删掉它，就再也还原不回官方原图了**（那时只能先解除只读，等客户端自己重新下载）。所以别把软件挪到别处后又指望它找回旧备份 —— 备份跟着 exe 走。

## 八、目录结构

```
icon.ico             exe / 窗口的应用图标
logo.png             界面顶栏标题前的图标（圆角显示）
img/                 效果预览参考图（游戏界面截图），程序把用户头像贴合到其中的头像框上
src/
  main.js              Electron 主进程：磁盘操作、IPC、EVE 进程轮询
  preload.js           contextBridge 安全桥（渲染层拿不到 Node 能力）
  core/
    paths.js           扫描各服缓存目录、识别服务器、服务器下拉项、尺寸→目录映射（含 Chat 分桶）
    launcher.js        读启动器本地数据，判断角色是否仍在启动器里
    logindex.js        日志目录索引（8 万文件不 stat，带 TTL 缓存）
    characters.js      扫描本机角色 ID（三来源并集）
    names.js           从游戏日志读角色名（含 UTF-16LE 识别）
    portrait.js        头像写入、只读开关、备份、恢复、尺寸索引、失败自动还原
    store.js           原图备份（每个角色一份，代表官方原版）
    system.js          检测 EVE 进程、目录可写性
renderer/
  index.html / style.css / app.js    界面 + 正方形裁剪器 + 效果预览轮播 + 免责声明（Canvas，无第三方图片库）
build/
  make-icon.py        生成 icon.ico（纯标准库）
  应用主界面.png       logo.png 的源图
```

> `原游戏头像备份\` 是**运行时生成**的目录（每个角色一份官方原图），不进版本库。

### 效果预览参考图

`img/` 下的每张截图都要在 `renderer/app.js` 的 `REFERENCE_FRAMES` 里配置头像框位置
（`rects`，按图片实际像素标定，一张图可以有多块，例如聊天框里的一排小头像）。
没有配置的图片会被跳过。贴合方式是 cover：头像铺满整个框、居中、不变形。
（参考图里的头像位已涂成白色，坐标按白块扫描得到，直接贴合白块即可。）
预览支持**自由缩放**：滚轮 / ＋－ 按钮 / 拖动平移 / 复位，按钮始终悬浮在图片上层。

## 九、技术栈

Electron 33 + 原生 HTML/CSS/JS。**运行时零第三方依赖** ——
裁剪、缩放、生成 JPEG 全部用浏览器原生 Canvas（`drawImage` + `toBlob`），
不需要 sharp / jimp 这类图像库。
